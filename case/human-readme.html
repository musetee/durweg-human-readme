Durweg 案例

写给人看的 README（照 aiagents-public 的做法）

用 Durweg 制作于 2026-10-31。工作流：human-readme。

方法

Task

给一个项目写 README（写给人看的首页），做到 aiagents-public 那样：第一次来的人在第一屏看懂项目解决什么问题，按自己的电脑选一条路装好，知道每天怎么用、文件在哪，跑通一个案例，并知道下一步去哪。

How I do it

  • 定核心：用一句话写出项目的核心价值和它解决的问题，作为 README 第一句；不讲故事，不罗列功能
  • 定读者和默认路径：默认写给第一次用的人；按电脑种类各给一行安装入口，写明容易混的情况走哪一行（如 Windows 里的 WSL 用 Windows 安装包）
  • 搭首页骨架，各自成节：安装（只写安装）→ 每天怎么用（编号小步，第一步写怎么打开终端）→ 文件放在哪里、怎么找到 → 案例（第一句说它展示什么、做出什么，引用每天的步骤）→ 我想……（一行一个任务加链接）→ 末尾的说明列表
  • 把细节移出首页：分步安装指南、特殊地区、卸载、参数和命令全表各放一页（中英两版），首页只留一句加链接
  • 实际走一遍：在新电脑或新 WSL 上照着首页从头做到案例成功，记下在哪里验证过、结果、哪些没验证
  • 用户以新手的眼光读，一条一条提意见
  • 按意见改这个项目的 README，中英文一起改，一次只改一件事
  • 每条意见改完后问用户：要不要变成通用规则；要的话更新 human-docs 规则（中英文和精简版）并在 CHANGELOG 写明原因
  • 重复“走一遍 → 读 → 改”，直到用户满意

Where it goes wrong

  • 第一句讲故事或罗列功能，看不出解决什么问题
  • WSL 用户把 Linux 那一行当成自己的
  • 新手不知道怎么进入终端或 WSL
  • 一段话里塞好几个动作，读不下去
  • 安装、每天怎么用、项目放在哪、试用混在一节里
  • 步骤里冒出的提示（如 Codex 的 “hooks are new or changed”）没解释，把新手吓住
  • 截图看不懂
  • 表格单元格太长
  • 没实际走一遍就说能跑通
  • 中文版和英文版不同步

Where I decide

  • 第一句（核心价值）怎么写
  • 每一轮改完的 README 我是否满意
  • 我提的新要求要不要变成通用规则

经验

  • README 第一句不讲故事，只说项目的核心价值、解决什么问题。
  • 写完一定要用新手的眼光读一遍：哪里读不下去，就改哪里，一次只改一件事。
  • 每节标题加 emoji；同样几项要比较的内容用表格，按顺序做的步骤用编号列表。
  • 真实用过才知道缺什么：比如先装 Codex、后装 Claude，就不知道 Claude 能不能用 Durweg，这种问题要写进常见问题。
  • 每条新要求改完都问一句：要不要变成以后所有项目的通用规则。

自己用这个工作流

装好 Durweg 以后，把工作流文件夹 human-readme 放进方法库（durweg library add <文件夹> --name human-readme），然后对 agent 说：“用 durweg 运行 human-readme”。
